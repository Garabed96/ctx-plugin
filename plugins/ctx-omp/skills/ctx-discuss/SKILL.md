# ctx-discuss — Explore before commitment

Do not edit files, create plans, or dispatch implementation work.

1. Establish the topic, current evidence, intended outcome, constraints, and decision horizon.
2. Read only relevant repository material; for UI discussion, consult `skill://ctx-discuss/references/ui-discuss.md`.
3. Ask focused questions with `ask` when the answer materially changes the options. Challenge assumptions without pretending uncertainty is a defect.
4. Offer grounded alternatives, tradeoffs, risks, and a recommendation. Clearly distinguish repository facts, user preferences, and inference.
5. End with the smallest appropriate next step: another decision, `skill://ctx-grilling/SKILL.md`, `skill://ctx-prd/SKILL.md`, `skill://ctx-lean/SKILL.md`, or `skill://ctx-plan/SKILL.md`.

A useful discussion reduces decision uncertainty; it does not quietly turn into implementation.
